# Architecture

CozyMix is one static page, exported with `output: "export"` and published on GitHub Pages. The build renders a calm splash screen; the app itself renders in the browser, because everything it shows (language, current mix, saved mixes) lives on the device. That choice removes hydration mismatches and any flash of the wrong language.

```text
src/
  app/          layout, page, web manifest (Next.js App Router)
  lib/          pure TypeScript, no React, no DOM: tested in Node
    base.ts       the base path (e.g. /cozymix on GitHub Pages) for files in public/
    catalog.ts    sounds and scenes: the single source of truth
    mix.ts        the mix model and its operations
    storage.ts    versioned localStorage formats and their parsers
    share.ts      share-link encoding (#mix=rain.65,wind.15)
    timer.ts      sleep-timer arithmetic
    i18n.ts       every user-facing string, English and Italian
  audio/
    dsp.ts        seeded noise, seamless loops, the synthesized sounds (pure, tested in Node)
    engine.ts     the Web Audio engine (browser only)
  ui/           React client components and hooks
    app.tsx       client gate, providers, shell, header, ambient glow
    store.tsx     all app state and actions, connected to the engine
    pad.tsx       sound pads (toggle + volume slider)
    collections.tsx  scenes and saved mixes
    dock.tsx      the always-visible player
    sheets.tsx    native <dialog> sheets: timer, save, about
    system.ts     service worker, offline status, install, media session, Space key
    locale.tsx · toast.tsx · slider.tsx · icons.tsx · persist.ts
  styles/       tokens.css (themes) → base.css → app.css
public/
  audio/        the six bundled recordings
  icons/        app icons (generated by scripts/make-icons.mjs)
  sw.js         the offline worker
scripts/
  postbuild.mjs  marks out/ for Pages (.nojekyll) and records the base path
  serve.mjs      static preview server for out/, used by `npm run preview` and Playwright
  make-icons.mjs · generate-nebulizer.mjs
```

## Data flow

```text
gesture ──▶ store action ──▶ setMix / setPlaying ──▶ effect ──▶ engine.apply(desired)
   │                                                               │
   └── engine.unlock()  (only here can audio start)                └─▶ snapshot ──▶ pads (loading / ready / error)
```

- **State** lives in one provider (`ui/store.tsx`): the `Mix` (`{ master, tracks: { id: { on, volume } } }`), `playing`, the saved mixes and the timer. Components read it with `useStore()`.
- **The engine is declarative.** An effect calls `engine.apply({ playing, master, levels })` after every change. The engine loads what is missing, ramps gains, releases sounds that are no longer wanted, and suspends the AudioContext 450 ms after a pause.
- **Starting audio needs a gesture.** Browsers block audio that starts on its own. `engine.unlock()` creates or resumes the AudioContext and is called only from click, tap and key handlers: toggling a sound on, Play, loading a scene, Undo. `apply()` never resumes. Restored mixes and shared links therefore always start paused.
- **Engine status** (`supported`, `running`, the per-sound `loading`/`ready`/`error`) reaches React through `useSyncExternalStore`.
- **One engine per page**, kept on `globalThis.__cozymixEngine`, so hot reloads do not stack AudioContexts. The browser tests read its output level there too.

## Audio

Graph: `voice gain` (one per sound) → `master` → `fade` (sleep timer) → `analyser` → speakers.

- **Volume curve**: gain = slider^1.5, which makes each step of the slider sound even.
- **Loops**: recordings are decoded, then `seamless()` blends their last *n* seconds into the first with an equal-power crossfade, so the buffer loops with no click. Each loop starts at a random offset.
- **Events**: thunder plays its whole recording 1.5–4 s after it is switched on, then every 18–55 s, at 0.9–1.1× speed.
- **Synthesis** (`dsp.ts`): brown noise is a leaky integrator under a slowly drifting two-pole low-pass and a gentle high-pass. It renders 36 s of stereo, with independent noise per ear. Every modulation period divides the loop length exactly, so the crossfade joins identical moments.
- **Safari**: `navigator.audioSession.type = "playback"` keeps sound on when the ringer switch is silent.

## Persistence

| Key | Contents |
| --- | --- |
| `cozymix.mix.v2` | The current mix. Restored on load, always paused. |
| `cozymix.saved.v2` | Up to 24 saved mixes `{ id, name, levels }`. |
| `cozymix.locale` | `"en"` or `"it"`, once the user picks one. |

The parsers never throw. Unknown sounds are dropped, levels are clamped, and invalid entries are skipped. If a format changes, add a new key and read the old one. When storage is blocked, the app keeps working in memory and says so.

## Deployment

- `next build` writes a static site to `out/`. `scripts/postbuild.mjs` adds `.nojekyll` and records the base path in `out/.base-path`.
- On GitHub Pages the site lives under `/<repo>/`. `NEXT_PUBLIC_BASE_PATH` sets Next’s `basePath`, which prefixes pages and scripts automatically. Files in `public/` (recordings, icons, the worker, manifest URLs) go through `asset()` from `lib/base.ts`, so they get the same prefix. `next.config.ts` rejects malformed values.
- `.github/workflows/deploy.yml` builds with `/<repo>` as the base path and runs every check and browser test against that build. On `main` it uploads `out/` and deploys it with `actions/deploy-pages`.
- `scripts/serve.mjs` serves `out/` at the recorded base path, so local tests see the same URLs as production.

## Offline

`public/sw.js` is registered only in production.

- **Install:** the worker precaches the page, the manifest, the icons, every recording, and the `/_next/static` files listed in the HTML. The page then posts any other scripts it loaded.
- **Fetch:** recordings come from the cache first. Everything else is network-first with a cache fallback, so an online visit always sees the newest version.
- **Activate:** the worker deletes older `cozymix-*` caches only, never other sites’ caches on a shared origin such as `github.io`. If it deleted any, it reloads the pages they controlled.
- **Base path:** the worker reads it from its own scope, so the same file works at a domain root and under `/cozymix/`.
- **Development:** the app unregisters every worker and clears every cache, so `npm run dev` never shows a stale build.

## Interface

- **Pads**: the toggle button (named after the sound, with `aria-pressed`) and a native range slider. The pad has `data-state` set to `off`, `loading`, `error`, `paused` or `playing`. The meter bars only animate when the state is `playing`, which means the engine is running and that sound’s buffer is ready.
- **Dock**: fixed at the bottom, within thumb reach. On phones it has two rows: Play, title and timer on top, then master volume, Save and Share. On wide screens it is a single row. While sound plays, the Play button glows with the analyser level.
- **Ambient glow**: up to four blurred radial gradients in the hues of the active sounds. They drift only while playing.
- **Sheets**: a native `<dialog>` with `showModal()`, which handles focus trapping, Escape, inert background and focus return.
- **Themes**: night by default, warm paper under `prefers-color-scheme: light`. Every colour is a token in `tokens.css`.
- **Motion**: every animation stops under `prefers-reduced-motion`.

## Localization

`lib/i18n.ts` holds the `en` dictionary and an `it` dictionary typed as `Messages`, so a missing Italian string fails the typecheck. Templates are functions (`count(n)`). The language is chosen from the saved choice, then `navigator.languages`, then English. Because the app renders only in the browser, the first frame is already in the right language.

## Testing

| Layer | Where | What |
| --- | --- | --- |
| Models and DSP | `tests/unit/*.test.ts` (Node’s test runner, TypeScript run natively) | Mix operations, parsers against hostile input, share links, timer maths, dictionary parity, generator levels, DC, stereo and loop seams. |
| Browser | `tests/e2e/*.spec.ts` (Playwright, the exported site served at its base path) | Real Web Audio: tests read `engine.level()`. Flows: playing, sliders, reload without autoplay, scenes with Undo, saving, retry after a failed download, shared links, Share, sleep timer (`page.clock`), Italian, no Web Audio, axe in both themes and in every sheet, focus return, 320–1440 px layouts, 44 px targets, keyboard use, offline (Chromium). |

Playwright’s WebKit build for Windows has no Web Audio, so tests that need sound skip themselves there. Real Safari still needs a manual check (see ROADMAP).

## Adding a sound

1. Verify the license and add it to `SOUND_SOURCES.md`, then put the file in `public/audio/`. For a synthesized sound, add a generator to `dsp.ts` instead.
2. Add an entry to `sounds` in `lib/catalog.ts`, and its id to `SoundId`.
3. Add the name and hint to both languages in `lib/i18n.ts`, and an icon under the same id in `ui/icons.tsx`. TypeScript fails until both exist.
4. Add the file to `AUDIO` in `public/sw.js` so it works offline (a unit test checks that the two lists match).
5. Run the checks. The unit tests confirm the file exists on disk.
